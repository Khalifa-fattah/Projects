# صاحِب — رفيق حفظ القرآن ومراجعته

تطبيق ويب عربي RTL لتنظيم مقاطع الحفظ، والمراجعة اليدوية، والاختبار بإخفاء النص، والجدولة، والإحصائيات، والنسخ الاحتياطي. يعمل بواجهة HTML/CSS/JavaScript وحدات ES، دون إطار واجهة أو اعتماديات تشغيل خارجية.

## التشغيل محليًا

لا تفتح `index.html` مباشرة عبر `file://`؛ وحدات JavaScript وService Worker تحتاج خادمًا محليًا أو HTTPS.

```bash
cd /mnt/agents/output/app
npm start
```

ثم افتح:

```text
http://localhost:8080
```

لا يحتاج التشغيل إلى `npm install`؛ أمر `npm start` يشغّل خادم Python المحلي. ويمكن بدلًا منه تشغيل:

```bash
python3 -m http.server 8080
```

عند الاستضافة، يجب تقديم المجلد كاملًا عبر HTTPS كي يعمل التثبيت وService Worker والعمل دون اتصال.

## البيانات والخصوصية

- المحفوظات والمراجعات والإعدادات والجدولة محلية في المتصفح الحالي فقط، باستخدام LocalStorage.
- لا يوجد حساب أو خادم خلفي أو مزامنة بين الأجهزة، ولا توجد خدمات تحليل أو تتبع.
- لا تُرسل المحفوظات أو الملاحظات إلى مصدر النص. الطلب الخارجي يخص السورة المطلوبة فقط.
- مسح بيانات الموقع، أو استخدام التصفح الخاص، أو تغيير الجهاز/المتصفح قد يفقد الوصول إلى البيانات. صدّر نسخة JSON دوريًا.
- مفاتيح النموذج الأصلي محفوظة دون تغيير:
  - `quran_hifz_entries_v1`
  - `quran_text_cache_v1`
- مفاتيح الإصدار الحالي:
  - `quran_review_sessions_v1`
  - `quran_settings_v2`
  - `quran_schedule_events_v1`
  - `quran_pre_import_backup_v1`

## النص القرآني والعمل دون اتصال

المصدر الشبكي هو Al Quran Cloud، إصدار `quran-uthmani`. يتحقق التطبيق من حالة HTTP، وبنية JSON، وهوية السورة، وعدد الآيات وتسلسلها، والنطاق المطلوب قبل عرض النص أو تخزينه. لا يولّد التطبيق نصًا قرآنيًا بديلًا ولا يعدّل الكلمات أو التشكيل آليًا.

لا تتضمن هذه النسخة قاعدة Quran كاملة مضمّنة. يوضح `data/quran-uthmani.meta.json` ذلك صراحة.

للتحقق من العمل دون اتصال:

1. افتح التطبيق عبر HTTPS أو localhost وأنت متصل، وانتظر اكتمال التهيئة.
2. افتح مراجعة لكل سورة تريد الاحتفاظ بنصها محليًا؛ لا تُخزّن السورة إلا بعد نجاح التحقق منها.
3. فعّل وضع عدم الاتصال من أدوات المتصفح، ثم أعد فتح التطبيق.
4. يجب أن تفتح الواجهة، وأن تعمل مراجعة السور التي سبق تخزينها.
5. عند طلب سورة غير مخزنة، يظهر خطأ صريح؛ لا تُسجّل مراجعة ناجحة.

ذاكرة Service Worker تحفظ ملفات التطبيق، أما نصوص السور فتبقى في مفتاح التخزين الأصلي. التخزين ليس دائمًا مضمونًا ضد الحذف أو ضغط المساحة.

## النسخ الاحتياطي والاستعادة

من «الإعدادات والبيانات»:

- **تصدير نسخة JSON**: ينزّل المحفوظات والمراجعات والإعدادات وأحداث الجدولة. لا يتضمن نص القرآن.
- **دمج دون تكرار**: يضيف السجلات الجديدة ويستبعد المطابق، مع إبقاء إعدادات الجهاز الحالية.
- **استبدال بعد نسخة احتياطية**: لا يتم إلا بعد تأكيد صريح، وتنزيل نسخة من الوضع الحالي، وحفظ نسخة إنقاذ محلية قبل الكتابة.
- عند تلف JSON أو بنية غير صالحة، لا يستبدل التطبيق الأصل بمصفوفة فارغة؛ يوقف الكتابة على المفتاح المتضرر ويتيح تنزيل البيانات الخام للإنقاذ.

لا يعني نجاح تصدير الملف وجود نسخة سحابية. احتفظ بالملف في مكان آمن خارج المتصفح.

## الوظائف المنفذة

- إضافة المقاطع وتعديلها وحذفها بعد تأكيد، مع تراجع مؤقت والاحتفاظ بسجل المراجعات.
- البحث والتصفية والترتيب، وكشف التداخل والتجاور، والدمج الصريح مع نقل سجلات المراجعة وحفظ المصادر.
- عدّ الآيات الفريدة دون تكرار حتى عند تداخل المقاطع، وفصلها عن عدد المقاطع وعن الآيات المختبرة.
- مراجعة عادية، واختبار حفظ، ومراجعة عشوائية، وجلسة يومية، وسورة/نطاق محدد مع تقسيم اختياري.
- إخفاء نص الآيات فعليًا من DOM أثناء الاختبار، وكشف آية منفردة أو كل النص.
- تقييم يدوي وملاحظات، وسجل مستقل للمكتمل وغير المكتمل، ومدة نشاط تستبعد التوقف.
- جدولة قاعدية قابلة للتفسير بحسب آخر تقييم والإتقان والتأخر والملاحظات، مع تأجيل وإعادة جدولة موثقة.
- إحصائيات وأهداف يومية وأسبوعية ونشاط متحرك لسبعة أيام يشمل اليوم والأيام الستة السابقة.
- مظهر نهاري وليلي، وخطوط وأيقونات محلية، وPWA manifest وService Worker وصفحة عدم اتصال.
- دعم لوحة المفاتيح، وحبس التركيز داخل الحوارات وإعادته بعد الإغلاق، وحالات تركيز ظاهرة وتقليل الحركة.

## إصلاحات مهمة عن النموذج الأولي

- استخدام التاريخ المحلي بدل اشتقاق اليوم من UTC، بما في ذلك اسم ملف النسخة الاحتياطية.
- منع إكمال المراجعة إذا فشل النص أو كان غير مطابق، ومنع تسجيل الإكمال مرتين عند تكرار الإرسال.
- فتح الجلسة وتحميل المحتوى والإكمال والتقييم والحفظ كمراحل منفصلة، مع إلغاء الطلبات المتأخرة.
- عدم استبدال البيانات القديمة أو التالفة تلقائيًا، والتحقق من قراءة القيمة بعد الكتابة وإظهار أخطاء المساحة والحفظ.
- إبطال الموعد اليدوي القديم عند وجود مراجعة مكتملة أحدث منه.
- إصلاح دمج النطاقات المتسلسلة والمتجاورة دون دمج صامت.
- إصلاح تباين أزرار الوضع الليلي، وقص الشعار، واستعادة التركيز بعد إعادة رسم بطاقة المقطع.

## الاختبارات المنفذة

### اختبارات آلية للمنطق

```bash
cd /mnt/agents/output/app
npm test
```

النتيجة النهائية: **23 من 23 ناجحة**. تشمل التواريخ والمناطق الزمنية، والنطاقات والتداخل والدمج، والجدولة، وحالة الجلسة، والإحصائيات، والترحيل، وتلف التخزين وأخطاء الكتابة، والتحقق من API، والنسخ الاحتياطي واستيراد 5000 مقطع.

### متصفح Chromium حقيقي

النتيجة النهائية: **79 من 79 حالة ناجحة** في ثلاث مجموعات:

- 24 حالة للمسار الأساسي والتداخل والاختبار والنقر المزدوج وفشل النص والتصدير وعدم الاتصال.
- 25 حالة للحذف والتراجع والبحث والتصفية والترتيب والعشوائي والتأجيل والاستيراد والتخزين التالف والردود المتأخرة.
- 30 حالة للمقاسات 375/768/1024/1440 بكسل، والنص الطويل، ولوحة المفاتيح، والوضع الليلي، وعدم وجود طلبات محلية 404 أو أخطاء Console.

استخدمت اختبارات المتصفح استجابات API متحكمًا بها ونصوصًا اصطناعية معلّمة بوصفها بيانات تحقق، وليست نصوصًا قرآنية أو بيانات مستخدم حقيقية. لذلك تثبت هذه الاختبارات سلوك التطبيق والتحقق والتخزين، لكنها لا تضمن توفر الخدمة الخارجية في كل وقت. لم يُختبر تغليف Android أو تشغيل APK.

في تشغيل محلي واحد، ظهرت 19 موارد بحجم مشفّر يقارب 813 كيلوبايت، وكان DOMContentLoaded نحو 146 مللي ثانية؛ هذه قراءة بيئة اختبار وليست معيار أداء عامًا لجميع الأجهزة.

## القيود الحالية

- لا توجد قاعدة Quran كاملة دون اتصال؛ السورة غير المخزنة تحتاج اتصالًا بالمصدر الأساسي.
- لا توجد مزامنة أو نسخة سحابية تلقائية، والبيانات مرتبطة بالمتصفح الحالي.
- التقييم يدوي بالكامل؛ لا يوجد كشف آلي لأخطاء التلاوة، ولا جدولة ذكاء اصطناعي.
- تسجيل المقطع لا يعني حفظه أو إتقانه؛ «متقن» يعتمد على تقييم المستخدم.
- قد تفرض المتصفحات حدودًا لمساحة LocalStorage أو تحذف بياناتها. تصدير النسخ الدورية مسؤولية المستخدم.
- لم يُنشأ APK، ولم تُجرَّب كل متصفحات Android أو جميع قارئات الشاشة على أجهزة حقيقية.

## المرحلة التالية المقترحة

1. توفير حزمة نص Quran كاملة موثقة المصدر والإصدار، مع بيانات تعريف وتحقق SHA-256، ليصبح النص كاملًا متاحًا دون اتصال.
2. اختبار المصدر الشبكي الفعلي وأجهزة Android الحقيقية وقارئات الشاشة، ثم إعداد تغليف Android وبناء APK/AAB فعليًا.
3. إضافة مزامنة اختيارية صريحة فقط إذا طلبها المستخدم، مع خادم ومصادقة وسياسة خصوصية وحل تعارضات؛ لا توجد حاليًا.
4. إضافة اختبارات متصفح قابلة لإعادة التشغيل ضمن المشروع، وتوسيع اختبارات التحديث والتخزين طويل الأمد.
